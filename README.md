# 车马慢 · Letters

一封需要等待的信。真实地理距离和参考动物速度决定等待时间。

## 现在能做什么

这是 v0.1 本机双人体验版：信箱、写信、马厩；邀请并接受后互相寄信；分身份保存草稿；选择信使；查看在途信件；到时拆信。内置一封明确标注的已抵达示例信，可以直接体验拆信。

- 原生微信小程序：miniprogram/
- 可在浏览器直接操作的预览：preview/
- 两者共享计算与信件规则：miniprogram/utils/model.js
- 产品讨论与参赛准备：根目录的中文 Markdown 文件

## 直接预览

在项目文件夹运行：

~~~sh
npm start
~~~

打开 http://127.0.0.1:4173 。服务仅监听本机，不向互联网发布，且仅提供预览所需的静态文件。

体验步骤：
1. 信箱点击“邀请对方”。
2. 顶部切换身份，由另一方接受。
3. 写信、选择信使、确认寄出。
4. 再切换身份，查看在路上的信。到达前不显示正文。
5. 可用阿禾身份查看“已收到”中的示例信。
6. 体验设置可以切换城市；寄出后的信不重新计算。

## 距离与时间：已做和未做

已做：
- 根据两个城市参考坐标，计算地球表面最短距离（平均地球半径 6371.0088 km）。
- 毫秒时长 = ceil(距离 km / 参考速度 km/h × 3600000)。
- 没有最低等待时间、最长等待时间、时间压缩倍率或提前拆信按钮。
- 寄出后复制位置、信使、速度和时间；后续改位置不改变已发信件。
- 预设大陆城市与东京之间的体验路线限制为小鸽。这只是预设地点规则。

未做／必须继续讨论：
- 尚未获取双方实时定位，也未接地图道路规划，陆上距离目前同样用两点最短距离。不能称为真实马匹道路长度。
- 固定参考速度来自真实资料，但不是某个品种、某匹马的连续长途平均速度。
- 未计休息、天气和信鸽航程限制；不能把该计算模型说成真实动物全程行程。
- 尚未加入用户提出的“距离很远时仅限快鸽”门槛，避免擅自规定公里数。
- 小马名字为角色名，不代表真实品种。养成、共同饲养和返回过程尚未实现。
- 新功能上线前应重新确认上述模型细节。

## 本机版的边界

这是一个可操作原型，尚非可上线的双人通信服务：
- 两个人是同一设备上的角色模拟，邀请不会发给真实好友。
- 原生版使用 wx 本地存储，浏览器版使用 localStorage；两端各自独立，不同步。
- 本机存储包含两方正文，时间使用设备时钟。UI 延迟拆信只用于体验，不是生产安全措施。
- 正式版必须由服务端保存信件、校验双方身份，并在服务器时间到达后才返回收信正文，不能提前把正文下载到收信端。
- 草稿和信件仅保存在当前设备／浏览器；清理站点数据或卸载会丢失。
- 并未接入真实微信邀请、内容审核、定位授权、订阅消息与部署；服务类目、备案和参赛规则仍需核实。
- 没有添加 AI 代写或其他未确认的 AI 功能。

## 多设备适配

- 手机：单栏布局，大按钮、底部安全边距，内容区域独立滚动。
- 平板／电脑：写信分两栏，信使卡片横向排列；内容最大宽度 880px，避免文字无限拉长。
- 横屏／较矮窗口：压缩顶部与导航，弹窗可以独立滚动。
- 原生小程序：补充横竖屏配置，将随屏宽过度放大的 rpx 调整为稳定字号并限制内容宽度；仍待微信开发者工具和真机确认。
